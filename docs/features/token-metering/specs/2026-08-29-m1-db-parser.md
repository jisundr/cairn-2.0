# Spec: M1 — `tool_uses` schema addition + `token-metering/parser.py`

Implementation spec for `ROADMAP.md`'s Milestone 1. Pins down the exact schema and function signatures so `builder` can implement without re-deciding shape. Design authority remains `03-architecture.md` (Capture side) and `02-requirements.md`; this spec adds nothing new at the design-decision level.

Implementation target is the `token-metering` git submodule (`cairn-2.0-token-metering`), not `tools/tokens/` in this repo — this repo keeps the design docs, the submodule keeps the code. The `tools/tokens/db.py`/`test_db.py` pair in this repo predates the split; carrying its `tool_uses` addition over to `token-metering/db.py` is part of implementing this spec, not a separate migration step.

## Architecture

Two changes, one commit: `db.py` gains a `tool_uses` table (needed before `parser.py`'s insert shape is locked in, per `ROADMAP.md`'s M1 note), and a new `parser.py` module walks a session's transcript once and writes every unique call, tool use, and usage-limit event into it.

`parser.py` is a pure library module — no CLI, no side effects beyond `db.py`'s insert helpers. `hooks/stop-tokens.sh` (M2) stays in this repo and is the only caller, reaching across the submodule boundary to invoke it; that hook is out of scope here, but M2 depends on `parse_session`'s signature below, so that signature is fixed now rather than left to M2 to invent.

## Components

### `token-metering/db.py` (extended)

New schema constant and helper, following `CALLS_SCHEMA`/`insert_call`'s existing shape:

```python
TOOL_USES_SCHEMA = """
CREATE TABLE IF NOT EXISTS tool_uses (
    tool_use_id TEXT PRIMARY KEY,
    request_id TEXT NOT NULL,
    session_id TEXT NOT NULL,
    agent TEXT,
    tool_name TEXT NOT NULL,
    detail TEXT,
    timestamp TEXT NOT NULL
)
"""
```

`connect()` executes it alongside the two existing `CREATE TABLE IF NOT EXISTS` statements.

```python
def insert_tool_use(conn, *, tool_use_id, request_id, session_id, agent, tool_name, timestamp, detail=None):
    conn.execute(
        "INSERT OR IGNORE INTO tool_uses "
        "(tool_use_id, request_id, session_id, agent, tool_name, detail, timestamp) "
        "VALUES (?, ?, ?, ?, ?, ?, ?)",
        (tool_use_id, request_id, session_id, agent, tool_name, detail, timestamp),
    )
```

`tool_use_id` (the block's own `toolu_...` id) is the primary key, giving the same `INSERT OR IGNORE` idempotency as `calls.request_id`. `detail` is the invoked skill name for a `Skill` tool call, `NULL` otherwise (per `03-architecture.md`) — the MCP server name is already embedded in `tool_name` (e.g. `mcp__claude-in-chrome__navigate`) and needs no separate column.

### `token-metering/parser.py` (new)

```python
def build_agent_map(main_entries: list[dict]) -> dict[str, str]
```
Single pass over the main transcript's already-parsed entries. Tracks each pending `Agent`/`Task` tool_use block by its `id`, keyed to `input["subagent_type"]`. When a matching `tool_result` entry (`tool_use_id` equal to a pending block's `id`) arrives, extracts the dispatched subagent's id from its text via `agentId:\s*([0-9a-f]+)` and records `{agentId: subagent_type}`. A tool_use with no corresponding tool_result (e.g. a truncated transcript) contributes nothing — never a `KeyError`.

```python
def parse_transcript(entries: list[dict], *, session_id: str, agent: str, conn) -> None
```
Walks one already-tagged stream of entries (the main transcript, or one `subagents/agent-*.jsonl` file) and calls `db.py`'s three insert helpers as appropriate per entry — see Data flow.

```python
def parse_session(cairn_dir: Path, transcript_path: Path, session_id: str) -> None
```
The M2 entry point. Opens the connection, loads the main transcript, builds the agent map, parses it tagged `agent="main"`, then parses every sibling `subagents/agent-<agentId>.jsonl` file tagged via the map (default `"unknown"`), and commits once at the end.

## Data flow

1. `parse_session` reads `transcript_path` line by line via a tolerant loader — each line is `json.loads`-parsed independently; a line that fails to parse is skipped, not fatal (mirrors `hooks/session-start.sh`'s silently-degrading style; capture is advisory, per §B10).
2. `build_agent_map` runs once over those parsed main-transcript entries.
3. `parse_transcript` classifies each entry:
   - `entry.get("isApiErrorMessage") is True` → `db.insert_usage_limit_event(session_id, timestamp, raw_entry=json.dumps(entry))`. Never reaches `calls`.
   - An assistant entry carrying `message.usage` and a top-level `requestId` → `db.insert_call(...)` with `model`/`timestamp` from the entry and token fields from `message.usage`. An entry with `usage` but no `requestId` is skipped (nothing to dedupe on) rather than inserted with a synthetic key.
   - Every `type: "tool_use"` block inside that same entry's `message.content` → one `db.insert_tool_use(...)` per block, sharing the entry's `request_id`; `detail` is `input.get("skill")` when `tool_name == "Skill"`, else `None`.
4. `parse_session` repeats step 3 for the main transcript (`agent="main"`) and for each `subagents/agent-<agentId>.jsonl` file, resolving `agent` from `build_agent_map`'s result (default `"unknown"`).
5. One `conn.commit()` after the full walk.

Exact field names inside `message.usage` (cache-read vs. the two cache-write buckets) should be confirmed against one real captured transcript during implementation — `db.py`'s existing column names (`cache_read_tokens`, `cache_write_5m_tokens`, `cache_write_1h_tokens`) are the target shape; a mismatch here is a one-line mapping fix, not a redesign.

## Error handling

- Malformed JSON line in either the main transcript or a subagent file → skipped, parsing continues.
- Assistant entry with `usage` but no `requestId` → skipped (can't dedupe).
- `isApiErrorMessage: true` → routed to `usage_limit_events`, never counted as a call.
- `agentId` with no entry in `build_agent_map`'s result → tagged `"unknown"`, never dropped.
- No `subagents/` directory for the session (no subagent dispatched) → treated as zero subagent files, not an error.
- Re-running `parse_session` against an already-recorded session → `INSERT OR IGNORE` on `request_id` and on `tool_use_id` means no duplicate rows and no error; this is the mechanism, not a special case, behind the full-rescan-on-every-`Stop` design already fixed in `03-architecture.md`.

## Testing

`token-metering/test_db.py` (extended, same `tmp_path` style as its existing tests):
- `tool_uses` appears in `sqlite_master` after `connect()`.
- `insert_tool_use` round-trips all fields, including a `None` `detail`.
- `insert_tool_use` dedupes on `tool_use_id` the same way `insert_call` dedupes on `request_id`.

`token-metering/test_parser.py` (new), synthetic fixture transcripts as literal JSONL written to `tmp_path`, mirroring `test_db.py`'s literal-dict fixture style:
- `build_agent_map` maps an `Agent`/`Task` tool_use's `subagent_type` to the `agentId` parsed from its matching `tool_result` text.
- `build_agent_map` returns nothing for a dispatched-but-unresolved tool_use (no matching `tool_result` in the fixture).
- `parse_session` on a two-file fixture (main transcript + one `subagents/agent-<id>.jsonl`) attributes the subagent's calls and tool uses to its resolved `subagent_type`, and the main transcript's own entries to `"main"`.
- `parse_session` tags a subagent file whose `agentId` has no match in the map as `"unknown"`.
- A duplicate `requestId` within a transcript inserts exactly one `calls` row.
- A duplicate `tool_use_id` inserts exactly one `tool_uses` row.
- An `isApiErrorMessage: true` entry lands in `usage_limit_events` and produces no `calls` row.
- One malformed JSON line in a fixture does not raise and does not block parsing of the surrounding valid lines.
- Running `parse_session` twice against the same transcript leaves row counts unchanged (idempotency).

Gate: `pytest test_db.py test_parser.py` inside `token-metering/`, per that repo's `.harness/workflow.md` — no `tools/budget.py` here, that gate is cairn-2.0's own and doesn't apply to the submodule.
