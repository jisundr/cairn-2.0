# Requirements: dashboard clean-SaaS redesign + routing, tooltips, drilldown-bar fixes

Five issues reported against the live `token-metering/frontend/` dashboard, each clarified by the user through follow-up. File:line references checked against `token-metering/` at this session's `HEAD`.

## Problem

**1. Nested "instrument window" card.** `Dashboard.tsx`'s root render wraps all page content in a bordered, backed card — `rounded-[6px] border border-(--paper-line) bg-(--window) px-7 py-6.5 shadow-[0_1px_0_var(--paper-line-soft)]` (`Dashboard.tsx:89-92`) — sitting on top of the page's own background. The user's report ("The main panel inside fo the bigger panel") and final clarification name this card, not the page's max-width, as the problem: "The current panel is working at all. I just want to remove the current background. Use the lighter background used as main backroudn. The content will stix in max-width." Resolved intent: drop the card's border/background/shadow chrome, paint one flat light background across the page, and keep the `max-w-[1180px]` centering that's already there.

**2. Tab state isn't in the URL.** `activeTab` in `Dashboard.tsx:35` is a plain `useState<DashboardTab>`, set only by `Header.tsx`'s `onTabChange` callback (`Header.tsx:57`) — confirmed by inspection, no `URLSearchParams`, `history`, or router import exists anywhere in either file. Reloading the page while on the Sessions tab drops the user back to Dashboard, per the user's report: "When moving to seesion tab and refresh it returns to dashbaord. The URL routing is missing here."

**3. No real chart tooltips.** Grepping `token-metering/frontend/src` for `Tooltip` returns zero matches — recharts' own `<Tooltip>` is never used despite `recharts` already being a dependency. `TokensPerDayPanel.tsx` renders three chart shapes by range (`shapeFor`, lines 57-61): `hourly` and `daily-click` are hand-rolled bar-and-SVG-overlay charts with no hover affordance at all, and `sparkline` (30d/month/6m/life) is a bare recharts `ComposedChart` with no `Tooltip` component. Only `daily-click` (the 7d view) surfaces any per-bar detail, and only via click into a `day-detail-panel` rendered below the chart (`TokensPerDayPanel.tsx:213-246`), not on hover. `ActivityHeatmap.tsx`'s cells carry a native, unstyled `title` attribute (`ActivityHeatmap.tsx:63`) — the browser's default tooltip, not a styled one. The user's report: "Tooltip is was not maximize for the graphs."

**4. Design system reads as generic/AI-generated.** The current "Bench Scope" system (`docs/DESIGN.md`) is a deliberately crafted bone/amber "instrument panel" look: CSS custom properties in `token-metering/frontend/src/index.css`, three custom font faces (Big Shoulders / Public Sans / Martian Mono), a solid-`--signal`-filled active-tab treatment (`components/ui/tabs.tsx:32`), uppercase tracked-letter-spacing pill/ghost buttons (`components/ui/button.tsx:13`), `Header.tsx`'s "Dial Tabs" with a `--signal-soft` fill plus inset box-shadow active state (`Header.tsx:64`), and `TokensPerDayPanel.tsx`'s hand-rolled graticule-grid background-image plus SVG polyline "calibrated trace" overlay (`TokensPerDayPanel.tsx:136-209`). The user's report: "Need to change the design system. It looks like a AI generated app." Asked to choose between finishing Bench Scope or starting over, the user chose a new direction outright, named **"Clean minimal SaaS"**: "Neutral grays/whites, subtle borders, one restrained accent color, generous whitespace — like Linear or Vercel's dashboard." This supersedes `docs/DESIGN.md` wholesale, not as an incremental patch.

**5. Drilldown per-agent bar carries no information on its own.** `SessionDrilldown.tsx`'s `AgentSelectRow` renders a mini progress bar (`agent-mini-bar-${name}`, lines 280-285) whose only signal is a CSS `width: ${(tokens / maxTokens) * 100}%` fill — no label, percentage, or tooltip on the bar itself. The row's other grid columns (`{calls} calls`, `{formatTokens(tokens)} tok`, `{formatCost(cost)}`, lines 286-290) do carry the raw numbers, but a viewer reading the bar alone gets nothing. The user's report: "In session details, if the progress bar is not giving any information of that graph. I'm thinking to revise that."

## Goals

1. `Dashboard.tsx`'s root element no longer renders a bordered/backed "instrument window" card around page content. The page uses one flat light background (the app's existing lighter/main background color, not a nested card color) behind all tabs' content.
2. Content stays width-capped and horizontally centered (the existing `max-w-[1180px]`-equivalent behavior is preserved) — only the card's border, background fill, and shadow are removed, not the width constraint.
3. Reloading the browser while `activeTab === "sessions"` keeps the user on the Sessions tab after reload; the same holds for Dashboard. Tab state round-trips through the URL (query param or path segment — see Open Questions) without a routing library dependency, unless justified otherwise (see Constraints).
4. Every chart in `TokensPerDayPanel.tsx` — `hourly`, `daily-click`, and `sparkline` shapes alike — surfaces its underlying per-bucket value (at minimum tokens, ideally cost/model breakdown where already computed) on mouse hover, not only via click.
5. `ActivityHeatmap.tsx`'s per-cell detail (day, hour, call count — and optionally tokens) is shown via a styled hover tooltip, replacing the native `title` attribute.
6. The dashboard's visual system is replaced end to end with "Clean minimal SaaS": neutral grays/whites, subtle borders, one restrained accent color, generous whitespace, in the spirit of Linear's or Vercel's dashboard — applied consistently, not left half-migrated between old and new tokens.
7. `token-metering/frontend/src/index.css`'s CSS custom properties (color tokens, and font-face declarations per the typography open question below) are redefined for the new system; no component is left referencing a removed Bench Scope token (`--signal`, `--ch1`–`--ch4`, `--bone`/`--bone-dim`/`--window`/`--block`, etc.) without an equivalent replacement.
8. Every component carrying Bench Scope's visual identity is restyled under the new system, at minimum: `components/ui/tabs.tsx` (solid `--signal`-fill active tab), `components/ui/button.tsx` (uppercase tracked pill/ghost variants), `Header.tsx`'s "Dial Tabs" segmented control, `TokensPerDayPanel.tsx`'s graticule background-image and SVG "calibrated trace" overlay, and the Meter Box / `Panel` / `HbarList` visual language used throughout `Dashboard.tsx`.
9. `docs/DESIGN.md` is rewritten (not incrementally patched) to document "Clean minimal SaaS" as the shipped system — its color palette, typography, component treatments — matching this repo's existing convention of keeping `DESIGN.md` synced with the shipped app.
10. `SessionDrilldown.tsx`'s `AgentSelectRow` mini progress bar conveys its value without requiring the viewer to read an adjacent grid column — e.g. via an in-bar label, percentage, or hover tooltip (exact mechanism is an open question, not locked here).

## Non-goals

- Any behavioral or correctness change to the data-capture pipeline (`db.py`, `parser.py`, `pricing.py`) or the SQLite schema — every issue here is UI-only; the redesign (Goal 4 issue) especially must not creep into touching how data is captured, computed, or stored.
- Any change to what data is fetched or how (`api/hooks.ts`'s query shapes, endpoints, or React Query configuration) beyond what's strictly needed to feed a tooltip or bar label with data the API already returns.
- Introducing a client-side routing library (e.g. React Router) — the URL-sync fix is scoped to work without one unless Constraints' justification bar is met.
- Any *other* redesign of information architecture — which panels exist, what each tab shows, the Dashboard/Sessions two-tab structure itself — this is a visual-system and interaction-polish pass, not a re-scoping of what the dashboard displays.
- `mockups/dashboard.html`, if it exists as a frozen design reference elsewhere in this repo's conventions, is out of scope for this task unless a future task names it explicitly.

## Constraints & assumptions

- Frontend stack is fixed: React 19, Vite 8, Tailwind v4, `recharts` 3.10, `@tanstack/react-query`, TypeScript — confirmed via `token-metering/frontend/package.json`. No routing library (`react-router`, `wouter`, etc.) is currently a dependency.
- No new frontend dependency should be added unless clearly justified — this applies most directly to the tab-routing fix (Goal 3): the default approach is `URLSearchParams`/`history.pushState` plus a `popstate` listener, hand-rolled in `Dashboard.tsx`/`Header.tsx`, not a router package. If that approach turns out to be impractical, the reason must be stated as an open finding rather than silently reached for a dependency.
- Gated by `token-metering/.harness/workflow.md`: `pytest test_*.py` clean, `npm run build` (regenerates `static/` — commit the rebuild, never hand-edit `tools/tokens/static/` directly), `npx playwright test` clean. After that, re-vendor the rebuilt `static/` into the outer repo's `tools/tokens/static/` and confirm `python tools/budget.py` is clean there.
- `docs/DESIGN.md` is assumed to need a full rewrite, not a diff — the new system is a different creative direction (Clean minimal SaaS vs. Bench Scope), not a tuned version of the same one, so patching its existing color/typography YAML frontmatter in place would leave stale prose describing a metaphor ("instrument panel," "Dial Tabs," "calibrated trace") that no longer matches the shipped app.
- The redesign (Goal 4 issue) is explicitly flagged as a deliberate, large-scope replacement of a working, intentional, previously-documented design system ("Bench Scope"), chosen by the user with full awareness that it touches nearly every visual component in the frontend — this is not a small fix and shouldn't be scoped or estimated as one.
- Playwright specs that assert on Bench-Scope-specific visual affordances (e.g. `data-testid="trace-overlay"`, styling-dependent selectors) may need updating to match the new system's markup — this is expected fallout of Goal 6-9, not a regression to avoid.

## Open questions

- **Exact "Clean minimal SaaS" token values.** The user settled the qualitative direction only — neutral grays/whites, subtle borders, one restrained accent color, generous whitespace, Linear/Vercel-inspired. Exact hex values, the specific accent color, border-radius scale, and spacing scale are undecided and need to be proposed during planning/build, not assumed here.
- **Typography under the new direction.** The current three-custom-font-face system (Big Shoulders / Public Sans / Martian Mono) is part of what makes Bench Scope's identity distinctive; the user did not say whether it's kept, partially kept (e.g. keep the monospace for tabular numbers), or fully replaced with a more conventional SaaS-dashboard typeface (e.g. a single system/Inter-like sans throughout). Needs a decision before `index.css`'s `@font-face` rules and `docs/DESIGN.md`'s typography section are finalized.
- **URL scheme for tab persistence — resolved, unconstrained.** Checked `server.py`'s `_serve_static_or_fallback` (line 934): any non-`/api/` request that doesn't match a real static file already falls back to `index.html` (the same catch-all previously used for the now-removed `/call/<session>/<n>` route). A path segment (`/sessions`) therefore survives a hard reload exactly as well as a query param (`?tab=sessions`) — no server-side change is needed either way. Left as a style choice for planning, not a technical constraint.
- **Drilldown progress-bar mechanism.** The user said "I'm thinking to revise that" — signaling intent, not a locked design. Candidate approaches (in-bar percentage text, a label on hover, an always-visible small numeral) should be proposed during planning rather than assumed here; the only fixed requirement is Goal 10's outcome (the bar conveys its value unaided).
- **Tooltip content depth per chart shape — mostly resolved.** Checked `api/types.ts`: every `TimeseriesPoint` (backing `hourly`, `daily-click`, and `sparkline` alike) already carries `bucket`, `calls`, `tokens`, and `cost` — tokens/cost/calls tooltips need no new API call on any shape. `ActivityHeatmap.tsx`'s cell aggregation (lines 34-41) already computes both `calls` and `tokens` locally; its current `title` only surfaces `calls`, so a tokens-inclusive tooltip is free. Genuinely open: whether the sparkline/hourly tooltips should also break down by model the way `daily-click`'s click-through `DayDetail.by_model` does today — that data is only fetched per-day via `useDayDetail` on click, so a hover-time model breakdown on the denser ranges would need a new fetch pattern. Left to planning to decide whether that depth is worth it, or whether bucket totals suffice everywhere but `daily-click`.

## Success criteria

- `Dashboard.tsx`'s root render has no border/background/shadow card wrapping page content; the page background is the same flat color across Dashboard and Sessions tabs; content remains width-capped and centered.
- Refreshing the browser while on the Sessions tab keeps the user on Sessions; refreshing on Dashboard keeps the user on Dashboard. No routing library appears in `package.json` unless a documented justification accompanies it.
- Hovering any bar in the `hourly`, `daily-click`, or `sparkline` chart shapes, and any cell in the activity heatmap, shows a styled tooltip with that bucket's/cell's value — verified for all three `TokensPerDayPanel` shapes and `ActivityHeatmap`.
- `docs/DESIGN.md` describes the shipped "Clean minimal SaaS" system (palette, typography, component treatments) with no residual Bench Scope-specific language ("instrument panel," "Dial Tabs," "calibrated trace," etc.) describing anything still present in the app.
- No component still references a removed Bench Scope CSS custom property; a full-repo search for `--signal`, `--ch1` through `--ch4`, `--bone`, `--bone-dim`, `--window`, `--block`, and `--paper-line*` turns up either the new system's replacements or nothing.
- The drilldown's per-agent mini bar communicates its share/value without requiring the viewer to read the adjacent `calls`/`tok`/cost columns.
- `pytest test_*.py`, `npm run build`, and `npx playwright test` stay green in `token-metering/` after the redesign; the rebuilt `static/` is re-vendored into `tools/tokens/static/` and `python tools/budget.py` is clean in the outer repo.
